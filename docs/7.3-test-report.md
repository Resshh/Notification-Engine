# Story 7.3 - Backend and Frontend Testing (data connectors)

Owner: Joice Mary Ajith. Scope: SQL Server connector, SAP HANA connector, mock-to-test switching, and the
screens that use them. Other owners test their own modules.

## 1. Automated backend tests

| What | File | How to run | Result |
|---|---|---|---|
| SQL Server connector rules (blocked SQL, production host, mock mode, no TLS bypass) | `server/tests/sqlServer.test.js` | `cd server`, `npm test` | pass |
| HANA connector | `server/tests/hana.test.js` | same | pass |
| Connectors through `executeQuery` (format, routing, passwords, safety) - 17 tests | `server/tests/connectorsEndToEnd.test.js` | same | pass |
| Real SQL Server (Docker test DB, 6 checks) | `db/sqlserver/check-connector.js` | Docker running and data loaded, `cd db\sqlserver`, `node check-connector.js` | 6 PASS (run 2026-11-10) |

What `connectorsEndToEnd.test.js` proves:
- SQL Server and HANA queries return `{ columns, rows, meta: { source, rowCount } }` with the right `source`.
- A SQL Server connection uses `sqlServer.js`; a HANA connection uses `hana.js`.
- Row limits apply, and a runtime limit overrides the saved one.
- The connector receives the decrypted password and no `passwordEncrypted`.
- The password is absent from results, from error messages, and from console output.
- DELETE, UPDATE, DROP and a second statement are blocked and never reach the connector.
- A production-looking host is refused (BR-02); an unknown type and a missing connection give clear errors.

Sanity check done: re-adding the broken export block to `sqlServer.js` makes 13 of these tests fail,
and removing the password cleaning in `executeQuery.js` makes the password test fail.

### Not covered by Jest (and why)
- The real `mssql` driver cannot load inside Jest (its dependency is ESM-only), so real-database checks
  run in plain Node through `check-connector.js`.
- Real SAP HANA and real Service Layer systems: only if the mentor provides test access.

## 2. Frontend manual tests

The only screen mounted in the client today is **Query setup** (menu: "Query setup" / "Queries"). Other menu items show a
placeholder. `ConnectionFormFields.jsx` exists but no page uses it yet.

Setup: MongoDB running; in `server` run `npm run seed` then `npm run dev` (http://localhost:5000); in `client` run
`npm run dev` (http://localhost:5173). To get connection IDs, open http://localhost:5000/api/queries in the browser:
each seeded query lists its `connectionId` (Overdue Invoices = SQL Server, Daily Sales Summary = HANA).
Fill in Result (Pass/Fail) and Notes while testing.

### Not testable in the browser yet (reported to the owners)
- **Connection form:** `ConnectionFormFields.jsx` is not used by any page, and the "Connections" menu item is a placeholder,
  so password masking, field validation and "no source contact when opening the form" cannot be checked in the UI.
- **Connection API from the browser:** `/api/connections` is behind `adminOnly`, but nothing sets `req.user`, so every request
  gets 401. The connection rules (admin only, password never returned, passwords encrypted) are covered by
  `server/tests/connectionCrud.test.js`, which uses a fake admin user.
Re-run the connection checks once a Connections page and login exist.

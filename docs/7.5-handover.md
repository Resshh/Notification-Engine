# Story 7.5 - Handover: SQL Server and SAP HANA connectors

Author: Joice Mary Ajith. Stories: 2.1, 2.2, 2.3, 3.2, 7.2.

## 1. What was built
- `server/connectors/sqlServer.js`: runs read-only SQL on a real SQL Server (test database in Docker) through `mssql`,
  or on the in-memory mock for any other database. Returns raw `{ columns, rows }`.
- `server/connectors/hana.js`: HANA queries (mock engine unless the HANA client and a real system are available),
  using the shared timeout and row limit.
- `db/sqlserver/`: Docker setup for the SQL Server test database, `load-mock-data.js` (loads `mock-data/demo`),
  and `check-connector.js` (6 checks against the real test DB).
- Shared modules used, not copied: `config/limits.js`, `security/validator.js`, `security/hostCheck.js`,
  `security/sanitiser.js`, `security/crypto.js`, `core/executeQuery.js`, `core/formatter.js`.

## 2. Safety rules (enforced in code)
- SELECT only; one statement; parameters go through the driver, never into the SQL text.
- 30 second timeout and 1000 row cap (`config/limits.js`).
- Passwords stored encrypted; decrypted only in `core/executeQuery.js`, passed to the connector, never returned or logged.
- Production-looking hosts or databases (prod, live, prd...) are refused (BR-02).
- TLS validation stays on. `rejectUnauthorized: false` appears nowhere in the code.
- The read-only SQL login (`readonly_user`) can only read; INSERT, UPDATE, DELETE and ALTER are denied by the database too.

## 3. Mock or real SQL Server (Story 7.2)
No code change: the connection's database name decides.
- Database listed in `SQLSERVER_REAL_DATABASES` (default `NotificationsTest`) uses the real SQL Server.
- Any other database name (for example `SalesTest`) uses the mock.
- The Docker test DB uses a self-signed certificate. For it only, set `SQLSERVER_TRUST_LOCAL_CERT=true` in `server/.env`;
  this only works when the host is `localhost` or `127.0.0.1`.
- For any other server, put the mentor's CA certificate file path in `NODE_EXTRA_CA_CERTS` (`server/.env`). No code change.

## 4. Run it from scratch
1. Docker Desktop running. In `db/sqlserver`: copy `.env.example` to `.env`, set both passwords, then
   `docker compose up -d`. Wait until `docker compose ps` says healthy.
2. In `db/sqlserver`: `node load-mock-data.js demo` (expect 20, 15, 20 and 30 rows).
3. In `db/sqlserver`: `node check-connector.js` (expect 6 PASS).
4. In `server`: copy `.env.example` to `.env`, set `MONGO_URI` and `ENCRYPTION_KEY`, add `SQLSERVER_TRUST_LOCAL_CERT=true`,
   then `npm install`, `npm run seed`, `npm run dev`.
5. In `client`: `npm install`, `npm run dev`.
6. The app cannot save a new connection from the browser yet (no Connections page, and the API needs a logged-in admin).
   To exercise the real test database, use `node check-connector.js`. To point a seeded connection at it, set its
   database to `NotificationsTest`, host `localhost`, port `1433`, username `readonly_user` and the `READONLY_PASSWORD`
   from `db/sqlserver/.env`.

## 5. Tests
`cd server` then `npm test`. See `docs/7.3-test-report.md` for what each test proves and the manual frontend checklist.

## 6. Demo script (about 5 minutes)
1. Show `docker compose ps` healthy and `node check-connector.js` printing 6 PASS (includes the wrong-password safe message
   and the blocked DELETE).
2. Open http://localhost:5000/api/queries to show the five seeded sample queries and their connection IDs.
3. Query setup: run the Overdue Invoices query on the SQL Server connection; preview shows up to 10 rows.
4. Type `DELETE FROM Invoices`: blocked.
5. Show that the seeded SQL Server connection database is `SalesTest` (mock). Explain that a database named
   `NotificationsTest` switches the same connector to the real test SQL Server (Story 7.2), no code change.
6. Run the Daily Sales Summary query on the HANA connection (mock).
7. Run `npm test` and show the connector tests passing.
